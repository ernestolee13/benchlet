# 채우기 단계

벤치 하나를 항목으로 채운다. 라벨 경로에 따라 방법이 다르다.

## 공통

- 생성기는 스크립트 + 시드. 실행하면 같은 항목이 나와야 한다
- 클래스마다 8건 이상. 클래스는 「무엇이 위반인가」의 종류(규칙 번호)나 분류 라벨
- 음성은 양성과 **같은 풀**에서 뽑는다. 음성이 표면 특징(길이·숫자 유무·키워드)만으로 갈리면 안 된다
- 항목마다 `evidence` 를 쓴다. 규칙 문장 또는 원문 위치
- 개인정보는 뽑는 즉시 치환한다. 사람 이름 → 역할, 회사 → 업종, 계정 → `user_1`
- 원자료 사본을 리포에 넣지 않는다. 항목 파일에는 본문이 들어가지만 원자료 전체는 아니다
- 만든 뒤 분포표를 낸다. 라벨 비율, 클래스별 수, 길이 분포(양성 대 음성), 정답 위치(다지)
- **단일 표면 특징 최선 정확도**를 낸다. 길이, 줄바꿈 유무, 콜론·인용부호·숫자 유무, 특정 어휘 유무 같은 특징 하나로 라벨을 찍었을 때 가장 높은 정확도. **70% 를 넘으면 그 특징을 깨는 항목을 더한다**(예: 인용문이 있으면 양성이 되는 벤치에는 「리서치에 이미 있는 인용문을 옮긴 음성」을 넣는다). 2026-09-30 sns 시험에서 둘이 여기 걸렸다
- 원자료가 잘린 미리보기(앞 N자)뿐이면 그대로 쓰되 매니페스트 `source` 에 명시한다. 장르마다 전문 유무가 다르면 **전부 미리보기로 통일**한다. 섞으면 길이가 라벨 신호가 된다
- `read_by_human` 은 사람이 읽었을 때만 true 다. 에이전트가 읽은 것은 `read_by_agent` 로 따로 적는다

## 라벨 경로 1: 있는 라벨 샘플링

- **먼저 행 수를 센다.** 발견 단계의 「예상 n」은 추정이다. 실제 행이 클래스별 최소(8건)에 못 미치면 이 벤치는 「나중」으로 내리고 심기로 채우지 않는다(2026-09-30 댓글 분류: 예상 수백 건, 실제 20행. 심어서 80건을 만들었지만 출처가 라벨 신호가 돼 보류했다)

- 상태 컬럼·verdict·정정 로그에서 **층화 샘플링**한다. 클래스별로 고르게, 시간대별로 고르게
- 생성하지 않는다. 라벨러(검증기)가 무엇인지 `provenance.verifier` 에 적는다
- 라벨러 자체를 사람이 표본 검사한다(20건). 검증기가 틀리면 라벨이 틀린다
- 양성이 한 템플릿에 몰려 있으면 나머지 클래스를 라벨 경로 2로 보강하고 그 항목은 `label_source: constructed` 로 따로 표시한다

## 라벨 경로 2: 규칙 심기

- 실제 데이터(음성 풀)에 규칙대로 결함을 심는다. 심는 위치와 방법은 클래스마다 표로 적는다
- **심은 결함이 다른 이유로 탐지되면 안 된다.** 비문·태 뒤집힘·주체 오류·내용 모순을 피한다. 우리 사례집(`lessons.md`) 참조
- 변조는 그럴듯해야 한다. 수치를 바꾸면 자릿수와 단위를 유지한다. 문장을 자르면 문장 경계가 아닌 곳에서 자른다
- 규칙에 hard/soft 등급이 있으면 hard 만 심는다
- 규칙이 「정확히 하나」를 준다고 말할 때는 실제로 유일한지 확인한다
- 심은 뒤 규칙 검증기가 있으면 돌려 보되, **검증기가 통과했다는 것은 라벨이 맞다는 증거가 아니다.** 사람이 전부 읽는다

## 라벨 경로 3: 패턴 모방 생성

- 실제 입력 10~20건을 씨앗으로 준다. 길이·주제·문체 분포를 실제와 맞춘다
- 생성한 뒤 길이·주제 분포를 실제 풀과 대조해 표로 보여 준다
- `label_source: judged`. 사람이 전부 읽고 근거를 확인한다
- 생성 모델과 검수 모델은 다른 패밀리여야 한다

## 산출

```
tasks/<bench>.dist.md       분포표와 심기 표, 읽은 항목 id 목록
```
